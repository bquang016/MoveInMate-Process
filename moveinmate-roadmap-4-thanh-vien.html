01 · Operating model

Hai lớp trách nhiệm

Vertical slice quyết định sản phẩm mỗi người bàn giao; vai trò xuyên suốt quyết định ai giữ chuẩn chung.

Quy tắc: “Phụ trách chính” nghĩa là đặt chuẩn, điều phối và chịu trách nhiệm đầu ra — không có nghĩa làm thay người khác. Mỗi module phải có đúng một owner và ít nhất một reviewer.

03 · Individual roadmaps

Roadmap riêng cho từng thành viên

Chọn thành viên để xem nhiệm vụ từng ngày, điểm phối hợp và đầu ra module.

TV1 — Onboarding & Integration Lead

Sở hữu luồng khai báo hồ sơ → sinh checklist → cập nhật tiến độ; giữ kiến trúc, contract và bản tích hợp chung.

Đầu ra cuối cùng

  • Onboarding Agent + prompt versioned
  • Profile/checklist API và database
  • Form profile + checklist UI
  • 10+ test cases và tài liệu module
Ngày 1Contract

Thực hiện

  • Chốt scope P0/P1/P2 và luồng end-to-end.
  • Thiết kế ResidentProfile, ChecklistItem, trạng thái workflow.
  • Tạo 20–30 hồ sơ giả lập, đánh dấu dữ liệu synthetic.
  • Dựng màn hình profile/checklist bằng mock.
Phối hợp: TV3 review khóa tenant và migration; TV2 review dữ liệu đầu vào AI; TV4 cung cấp UI kit.
Review bởi: TV2.
Ngày 2Agent core

Thực hiện

  • Xây graph: profile → build_checklist → guide → track.
  • Ép output qua schema và fallback khi model lỗi.
  • Viết unit test cho rule bắt buộc/không bắt buộc.
Nhận từ: TV2 prompt convention.
Hỗ trợ: TV3 setup database local.
Review bởi: TV2.
Ngày 3API + UI

Thực hiện

  • Hoàn thiện API tạo profile, sinh/lấy/cập nhật checklist.
  • Kết nối frontend với API; đủ loading/error/empty state.
  • Demo happy path và missing-information path.
Nhận từ: TV4 component chuẩn.
Hỗ trợ: TV3 auth middleware.
Review bởi: TV4 UI, TV3 API.
Ngày 4Integration

Thực hiện

  • Gắn citation link sang trợ lý RAG khi người dùng cần hướng dẫn.
  • Đẩy hồ sơ cần duyệt sang queue HITL của TV4.
  • Chạy integration test với mock adapter và API thật.
Phối hợp: TV2 cho query contract; TV4 cho approval contract.
Review bởi: TV2 + TV4.
Ngày 5Security

Thực hiện

  • Thêm tenant filter và audit event cho thay đổi checklist.
  • Test cư dân không sửa checklist người khác.
  • Hỗ trợ TV3 smoke test Docker/deploy.
Owner security: TV3.
TV1 cung cấp: endpoint inventory và test fixture.
Review bởi: TV3.
Ngày 6QA + report

Thực hiện

  • Chạy regression end-to-end toàn sản phẩm.
  • Chụp evidence và viết kiến trúc + agent design.
  • Đóng lỗi P0, xác nhận tiêu chí nghiệm thu module.
Hỗ trợ: cả nhóm chạy test module.
Review tài liệu: TV4.
Review kỹ thuật: TV3.
Ngày 7Release

Thực hiện

  • Code freeze, quản lý merge/release tag.
  • Chạy rehearsal end-to-end và chuẩn bị dữ liệu reset demo.
  • Chốt known limitations và phương án fallback.
Phối hợp: TV3 deploy; TV4 demo script; TV2 reset vector index.
Sign-off: cả nhóm.

TV2 — RAG & Data/AI Quality Lead

Sở hữu corpus → chunking → embedding → retrieval → citation; đặt chuẩn dữ liệu, prompt và evaluation cho toàn nhóm.

Đầu ra cuối cùng

  • Corpus manifest và data dictionary
  • Ingestion/query API + RAG UI
  • So sánh 2 cách chunking
  • 20–30 golden questions + eval report
Ngày 1Corpus

Thực hiện

  • Chốt nguồn tài liệu, bản quyền, version và metadata.
  • Tạo corpus manifest; phân biệt real/synthetic.
  • Định nghĩa chuẩn prompt/output AI dùng chung.
  • Dựng UI chat bằng response mock có citation.
Nhận từ: mọi thành viên cung cấp tài liệu nghiệp vụ.
Hỗ trợ: TV1 xác nhận scope thủ tục.
Review bởi: TV1.
Ngày 2Ingestion

Thực hiện

  • Làm fixed-size 500–700 tokens, overlap 80–120.
  • Làm heading-aware; fallback sang fixed-size với mục dài.
  • Index embedding 768D vào collection riêng theo model/version.
Hỗ trợ: TV3 volume/config Docker.
Review bởi: TV1 kiểm tra cấu trúc nghiệp vụ.
Ngày 3Retrieval

Thực hiện

  • Xây retrieval filter theo community/version/visibility.
  • Prompt trả lời có nguồn và từ chối khi thiếu bằng chứng.
  • Hoàn thiện API ingestion/query và kết nối UI.
Nhận từ: TV3 auth context.
Hỗ trợ: TV4 citation component.
Review bởi: TV4 về UX tin cậy.
Ngày 4Evaluation

Thực hiện

  • Tạo 20–30 golden questions có expected source.
  • Đo Hit@3, citation correctness, answer correctness, refusal.
  • So sánh chunking và chốt cấu hình production.
Hỗ trợ: TV4 xây rubric/judge form; TV1 cung cấp câu hỏi onboarding.
Review bởi: TV1 + TV4.
Ngày 5Safety

Thực hiện

  • Test prompt injection trong tài liệu và câu hỏi.
  • Test không trả tài liệu sai community.
  • Review prompt + schema AI của TV1, TV3, TV4.
Phối hợp: TV3 security test; từng owner sửa module của mình.
Review bởi: TV3.
Ngày 6Optimize

Thực hiện

  • Đo latency, số token, số chunk và lỗi retrieval.
  • Chốt top-k, threshold và fallback.
  • Viết phần RAG/chunking/evaluation của báo cáo.
Hỗ trợ: TV4 chuẩn hóa biểu đồ/bảng.
Review bởi: TV1.
Ngày 7Evidence

Thực hiện

  • Reset/re-index corpus demo có kiểm soát.
  • Xuất eval report cuối và chụp citation evidence.
  • Chuẩn bị 2–3 câu hỏi demo ổn định và 1 câu fallback.
Phối hợp: TV1 rehearsal; TV3 production logs; TV4 slide số liệu.
Sign-off: TV1.

  • Thiết kế bảng service_requests/request_events.
  • Dựng UI tạo ticket/timeline bằng mock.
Nhận từ: TV1 scope nghiệp vụ; TV2 data convention; TV4 UI kit.
Review bởi: TV2.
Ngày 2AI routing

Thực hiện

  • Xây prompt/classifier trích category, location, priority.
  • Validate output bằng schema.
  • Viết deterministic rules cho urgent/fee/limit.
Hỗ trợ: TV2 review prompt và test set.
Review bởi: TV2.
Ngày 3Backend

Thực hiện

  • Hoàn thiện create/list/detail/update ticket API.
  • Gắn auth context, audit event và idempotency cơ bản.
  • Kết nối frontend, hiển thị kết quả AI có thể sửa trước khi gửi.
Nhận từ: TV4 component/form states.

04 · Quality gates

Tiêu chí kiểm thử, đánh giá và hoàn thành

Một task không được chuyển Done chỉ vì “chạy được trên máy người làm”.

Kiểm thử bắt buộc

  • Happy path và ít nhất 1 failure path.
  • Validation input/output và API status đúng.
  • Loading, empty, error, success state.
  • Tenant isolation với hộ A/hộ B.
  • Smoke test trên môi trường deploy.
  • Regression test trước release.

Đánh giá AI

  • Output đúng JSON/schema.
  • Correctness và grounding có evidence.
  • Không tự tính phí/hạn mức bằng suy đoán.
  • Có fallback khi thiếu thông tin.
  • Không tiết lộ dữ liệu tenant khác.
  • Ghi model, prompt version, latency.

Definition of Done

  • Code đã review và merge.
  • Test/evidence đính kèm.
  • Không có secret trong repo.
  • API đúng contract, migration chạy sạch.
  • Tài liệu chạy và bàn giao đầy đủ.
  • Demo được trên URL chung.

Rubric đánh giá module

Ngưỡng nghiệm thu MVP

  • RAG: Hit@3 ≥ 80% trên golden set và citation đúng tài liệu.
  • Checklist: ≥ 90% expected items trên test profiles.
  • Routing: macro-F1 hoặc accuracy ≥ 80% trên test set cân bằng.
  • HITL: 100% quyết định nhạy cảm cần hành động BQL.
  • Security: 0 trường hợp cross-tenant trong test bắt buộc.
  • Stability: 100% luồng P0 qua smoke test production.

06 · Release control

Checklist trước khi bàn giao cuối

Code freeze trước giờ trình bày tối thiểu 12 giờ; sau freeze chỉ sửa lỗi P0.

Technical release checklist

  • Frontend, backend, database và vector store khởi động từ hướng dẫn sạch.
  • Migration + seed chạy thành công trên môi trường mới.
  • Không có API key, secret hoặc PII thật trong repository/log.
  • Tất cả endpoint P0 có auth, authorization và error handling.
  • 4 luồng P0 qua end-to-end smoke test production.
  • Có demo account, dữ liệu reset và phương án offline/video.

Report & demo checklist

  • Số liệu báo cáo khớp kết quả test và slide.
  • Mỗi thành viên có phần AI, backend/frontend và evidence riêng.
  • Có sơ đồ kiến trúc, agent graph, RAG pipeline và HITL flow.
  • Nêu rõ data thật, data synthetic, nguồn và giới hạn.
  • Demo đã bấm giờ, có người điều khiển và người thuyết trình.
  • Known limitations và hướng phát triển không bị trình bày như tính năng đã có.
